# smart_scale — кухонные весы с камерой

## Цель
Весы с камерой и приложением для автоматического учёта калорий: продукт кладут на весы, камера распознаёт еду (и/или штрихкод), вес и продукт логируются без ручного ввода. Целевая розничная цена — 2–3 тыс. ₽, поэтому железо должно быть дешёвым. Модель распознавания дообучается и хостится на своём сервере.

## Железо прототипа
- **ESP32-CAM (AI Thinker)** + шилд **ESP32-CAM-MB** (USB через CH340, кнопки IO0 и RST), камера **OV2640** (до 2 Мп), внешняя Wi-Fi антенна
- **Тензодатчик до 5 кг** + АЦП **HX711** — подключены
- **OLED 128×64** (I2C) и **сканер штрихкодов** (UART) — подключены
- Беспаечная макетная плата на 400 точек
- Разработчик впервые работает с электроникой и **никогда не паял**: любые шаги с пайкой или проводкой описывать максимально подробно и пошагово

## Стек
- **Прошивка:** C++, PlatformIO, framework Arduino, платформа espressif32
- **Обработка:** Python — приём видеопотока, классификация (OpenCV, numpy, requests)
- **Окружение:** macOS (Apple Silicon), VS Code + PlatformIO IDE

## Прошивка (scale_controller)
`platformio.ini`:
```ini
[env:esp32cam]
platform = espressif32
board = esp32cam
framework = arduino
upload_speed = 460800
monitor_speed = 115200
monitor_rts = 0        ; обязательно для шилда MB, иначе плата висит в сбросе при открытом мониторе
monitor_dtr = 0
build_flags =
    -DBOARD_HAS_PSRAM
    -mfix-esp32-psram-cache-issue
```

`main.cpp` — подключение к Wi-Fi (только 2.4 ГГц, сеть `TP-Link_1246`; SSID/пароль в `.env` → макросы `WIFI_SSID`/`WIFI_PASS` через `load_env.py`), камера в JPEG, два HTTP-сервера на `esp_http_server`:
- `http://<IP>/capture` (порт 80) — один JPEG-кадр **всегда UXGA 1600×1200, quality 10**: камера переключается на время снимка (3-й кадр нужного размера, копия в PSRAM) и возвращается в режим стрима
- Стрим по умолчанию VGA, quality 20 (~8 КБ/кадр) — ради скорости на слабом Wi-Fi
- `http://<IP>:81/stream` — MJPEG-поток (отдельный сервер, чтобы `/capture` работал во время стрима)
- `http://<IP>/control?var=framesize|quality|led&val=N` — настройки на лету (буферы выделены под UXGA, старт в VGA)

Штрихкоды (замер 23.10.2026, EAN-13 с 20–25 см): яркости без вспышки мало, с вспышкой (`led=1`) контраст есть, разрешения SXGA/UXGA хватает (~3 px на полоску), но заводской фокус объектива — на дальние предметы, узкие полоски сливаются → zxing не читает. Нужно подкрутить объектив на ближний фокус: `image_handler/focus.py` показывает резкость и результат zxing вживую.

С PSRAM: VGA 640×480, jpeg_quality 12, 2 буфера, `CAMERA_GRAB_LATEST`. Без PSRAM: QVGA. IP выводится в Serial Monitor после старта; плата также доступна по имени `esp32cam.local` (mDNS), `camera.py` резолвит его в `ESP_IP` при импорте — IP руками не менять.

Пины камеры AI Thinker: PWDN 32, RESET -1, XCLK 0, SIOD 26, SIOC 27, Y9..Y2 = 35, 34, 39, 36, 21, 19, 18, 5, VSYNC 25, HREF 23, PCLK 22. Вспышка — GPIO 4.

Помимо камеры прошивка (09.11.2026) умеет:
- **HX711:** каждые 500 мс печатает `raw` и вес в граммах; `t` — тара, `c<граммы>` — калибровка по эталону, коэффициент и смещение хранятся в NVS
- **OLED:** показывает IP, вес (или raw, пока нет калибровки), последний штрихкод; сам перебирает SDA/SCL и адреса `0x3C/0x3D`
- **Сканер:** активен по умолчанию, читает строки из `Serial2` (9600 8N1, RX=GPIO16) и печатает `[BARCODE] <код>` в консоль
- **Консольные команды:** `h`, `w`, `t`, `c500`, `f-7050`, `i`, `p16`, `b9600`, `e`/`d`, `o2 15`

## Python-клиент
- Один кадр: `requests.get(/capture)` → `cv2.imdecode` → BGR `np.ndarray`
- Поток: `cv2.VideoCapture("http://<IP>:81/stream")`, в цикле `cap.read()`

## Прошивка платы: процедура
1. ESP32-CAM вставляется в MB по подписям пинов (5V к 5V, GND к GND); USB-кабель должен передавать данные
2. Upload (→ в нижней панели PlatformIO). Шилд MB сам переводит плату в режим загрузки через DTR/RTS
3. Если `Failed to connect` или `Wrong boot mode`: во время `Connecting...` зажать IO0, нажать RST, отпустить IO0
4. После прошивки: Serial Monitor и RST

Режим загрузки ESP32 определяется уровнем GPIO0 при сбросе: LOW — прошивка, HIGH — запуск программы.
## Текущая схема подключения (прототип)

### Компоненты
- **ESP32-CAM (AI Thinker)**, вынута из шилда MB, подключена проводами Dupont
- **ESP32-CAM-MB** — используется только как USB-UART адаптер (CH340), соединён с ESP32-CAM проводами
- **HX711 (XFW-HX711)** — гребёнка GND/DT/SCK/VCC запаяна, модуль стоит на макетке (каждый пин в своём столбце)
- **Тензодатчик 5 кг** — подключён к HX711
- **OLED 128×64, 7 пинов** (GND/VDD/SCK/SDA/RES/DC/CS) — работает по I2C: `RES` на VDD, `DC` и `CS` на GND, сигналы только `SCK`/`SDA`
- **Сканер штрихкодов** (GM65/GM803-подобный) — UART, 9600 8N1, по умолчанию в режиме непрерывного сканирования

### ESP32-CAM ↔ шилд MB (одноимённые контакты)
| MB | ESP32-CAM |
|---|---|
| 5V | 5V |
| GND | GND (через общий столбец на макетке) |
| U0R | U0R |
| U0T | U0T |
| IO0 | IO0 |

Цвета проводов в разных перерисовках схемы менялись — ориентируйся на подписи контактов, а не на цвет.

### ESP32-CAM ↔ HX711
| HX711 | ESP32-CAM | Провод |
|---|---|---|
| VCC | 3V3 (НЕ 5V — DT выходит с уровнем питания) | красный |
| GND | GND (общий столбец на макетке с GND шилда) | белый |
| DT | IO13 | синий |
| SCK | IO14 | |

### ESP32-CAM ↔ OLED 128×64 (7 пинов, режим I2C)
| OLED | Куда | Примечание |
|---|---|---|
| GND | GND | |
| VDD | **3V3** | если на модуле нет стабилизатора, 5 В его убьёт |
| SCK | IO15 | это SCL |
| SDA | IO12 | **на этой плате IO12 повреждён** — при необходимости переставить на IO2 |
| RES | VDD | в I2C-режиме |
| DC | GND | в I2C-режиме |
| CS | GND | в I2C-режиме |

Прошивка при старте сама перебирает `SDA/SCL` и адреса `0x3C/0x3D`, поэтому случайно перепутанные SDA/SCL не страшны.
Если дисплей не находится — `i` в консоли покажет адреса на шине.

### ESP32-CAM ↔ сканер штрихкодов
| Сканер | ESP32-CAM | Примечание |
|---|---|---|
| VCC | 5V | GM65/GM803 питаются от 5 В |
| GND | GND | |
| TX | IO16 | это RX второго UART (`Serial2`) |
| RX | 3V3 | сканер только передаёт; команды ему не шлём |

Скорость по умолчанию **9600 8N1**, сканирование непрерывное. Если сканер другого типа — скорость
меняется командой `b<baud>`, пин RX — командой `p<gpio>` без перепрошивки.

Свободные: IO2, IO4 (вспышка), IO0 (XCLK камеры — не занимать). IO12 — только если очень нужно (повреждён).

### HX711 ↔ тензодатчик (когда подключён)
Красный → E+, чёрный → E−, белый → A−, зелёный → A+. Провода нужно **запаять** — вставленные в отверстия без пайки не дают контакта.

### Прошивка в этой схеме
**Надёжный способ (27.10.2026): прошивать, вставив ESP32-CAM прямо в шилд MB** — автосброс, без кнопок, с первой попытки.
На макетке прошивка шла через раз: `boot:0xf` вместо `boot:0x3` (IO2/IO4 читались как 1), `Failed to connect`,
`Failed to start stub flasher`. В шилде та же плата — `boot:0x13`, всё штатно → виновата проводка/контакты макетки.
**Причина (27.10.2026): повреждён вход GPIO12** (вероятно, 5 В при горячем подключении провода 5V рядом с пинами):
IO12 всегда «1» → по strapping флеш получала 1.8 В вместо 3.3 В → `Manufacturer: ff`, `invalid header: 0xffffffff`,
`Serial data stream stopped`. **Прожжён eFuse `set-flash-voltage 3.3V`** (XPD_SDIO_FORCE/REG/TIEH = 1, необратимо) —
плата игнорирует IO12, флеш 68/4016 4 МБ, грузится при `boot:0x33`. IO12 на этой плате не использовать.
Вспышка от касания пальцем — наводка на ненастроенный IO4, не признак контакта. Тест HX711 мигает вспышкой («пульс»).
Провод 5V на горячую не передёргивать: бросок тока сбрасывает USB-адаптер шилда (порт пропадает).
Если всё же на проводах, вручную:
1. Снять 5V → зажать IO0 на шилде → вернуть 5V → отпустить IO0
2. Upload (`upload_speed = 115200`; на проводах высокая скорость сбоит)
3. После `SUCCESS` передёрнуть 5V без кнопки, чтобы запустить программу
4. Serial Monitor открывать ДО передёргивания 5V, иначе вывод `setup()` пропадёт. Перед Upload монитор закрыть (занимает порт)
5. Если монитор пустой даже без загрузочного лога ESP32 — плата не перезагрузилась (подпитка через UART-линии): переподключить USB целиком

### Диагностика HX711 (история)
- Связь ESP32 ↔ HX711 работает: `scale.read()` возвращает данные
- С подключённым датчиком почти все значения `0x7FFFFF` (зашкал) + случайные числа и нули → вход A+/A− висит в воздухе. Причина — провода тензодатчика не запаяны
- Тест исправности HX711: перемкнуть A+ и A− → должно быть стабильное небольшое число
- Вспышка мигала при нажатии на провода → плохой контакт по питанию (перезагрузка) или провод касался IO4. Рекомендуется перенести ESP32-CAM на макетку (поперёк канавки, пины в рядах b и i)
- В `src/` должен лежать только один файл с `setup()`/`loop()`; старые версии хранить в `backup/`

### Проверочные скетчи
- `raw`-тест: `scale.begin(13, 14)`, печать `scale.read()` в hex каждые 500 мс
- Поиск DT: IO14 = OUTPUT LOW, IO2/12/13/15 = INPUT_PULLUP; пин с `0` — это DT

## Известные проблемы и решения
- **`Guru Meditation ... LoadProhibited` в `esp_camera_init` после добавления OLED:** `Wire` (I2C0) инициализировался до камеры, а SCCB камеры использует **I2C1** (`CONFIG_SCCB_HARDWARE_I2C_PORT1`). Решение: OLED на I2C0 (`Wire`) с минимальным числом `begin/end`, камера инициализируется первой, при её ошибке плата продолжает работу без камеры.
- **Нет кнопок PlatformIO, красные `#include`:** проект вложен в `smart_scale/`, а PlatformIO ищет `platformio.ini` только в корне открытой папки → File → Add Folder to Workspace → `scale_controller`
- **Красные `FreeRTOS.h`/`esp_camera.h` при успешной сборке:** Arduino-ESP32 3.x передаёт пути ESP-IDF через `@flags/includes`, IntelliSense его не читает → `ide_includes.py` (`extra_scripts` в `platformio.ini`) раскрывает пути при генерации `.vscode`; после изменений — PlatformIO → Rebuild IntelliSense Index
- **Кнопка ▶ (Code Runner) на `main.cpp` даёт ошибки:** она компилирует файл обычным g++ для Mac; прошивку собирать только кнопками PlatformIO (✓ Build, → Upload)
- **`pio run` висит после `Processing esp32cam`:** зависшие старые процессы держат блокировку → закрыть VS Code (Cmd+Q), `pkill -9 -f platformio`, проверить через `ps aux | grep -i "[p]latformio"`
- **`No space left on device` при установке:** тулчейны и фреймворк ESP32 занимают 2–3 ГБ, нужно ≥5 ГБ свободного места. Очистка недокачанного: `rm -rf ~/.platformio/.cache`
- Ставить пакеты из папки проекта (`~/.platformio/penv/bin/pio run`), а не через `pio pkg install -g --platform espressif32` — глобальная установка тянет лишние тулчейны (например, riscv32)
- `Brownout detector` или перезагрузки → не хватает питания: подключать напрямую в порт компьютера, без хаба, коротким кабелем
- **Бесконечные точки `Connecting to Wi-Fi...`:** SSID чувствителен к регистру (было `TP-LINK_1246` вместо `TP-Link_1246`), сеть должна быть 2.4 ГГц (`_5G` не подойдёт), проверить пароль в `.env`
- **Стрим 1–3 к/с, потери пакетов при нормальном RSSI (−61 dBm):** XCLK камеры 20 МГц глушит Wi-Fi (121-я гармоника = 2420 МГц, канал 3 роутера) → `xclk_freq_hz = 10000000`: стало 12.5 к/с, снимок 70–130 мс, ping ~20 мс
- **`esp32cam.local` → `127.0.0.200`, ConnectTimeout:** VPN Happ (sing-box) подмешивает фиктивный адрес; `camera.py` отбрасывает `127.*` из `gethostbyname_ex`. Браузер может всё равно открыть не тот адрес — тогда по IP
- `Camera init failed 0x105/0x20004` → переподключить шлейф камеры в разъёме
