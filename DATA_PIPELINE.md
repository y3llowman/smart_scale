# Датасет: как устроен и как с ним работать

## Коротко

1. Положить фото в `custom_dataset/raw/<класс>/` — имя папки и есть метка.
2. Запустить из папки `smart_scale`:
   ```
   .venv\Scripts\python build_dataset.py
   ```
3. Если добавились фото штрихкодов — один раз проверить их в CVAT (раздел 5), экспорт положить в
   `custom_dataset/cvat/verified/`, запустить скрипт ещё раз.
4. Учить на `custom_dataset/dataset/` (`images/` + `labels.csv`), train/test делить самому (раздел 7).

Других шагов и конвертаций нет.

## 1. Папки

```
custom_dataset/
  raw/                        ВЫ кладёте фото; скрипт здесь ничего не меняет
    barcodes/IMG_6883.HEIC      класс «штрихкод/упаковка» — любой продукт, главное код
    apples/IMG_8155.JPG         остальные классы — еда, по папке на класс
  esp32/<класс>/esp_*.jpg     ВЫ снимаете с настоящей ESP32-CAM (scale_controller/image_handler/shoot.py);
                              build_dataset.py их НЕ трогает — это реальные кадры для теста и калибровки ov2640_sim
  cvat/
    upload.zip                СКРИПТ: фото штрихкодов, которые ещё не проверены в CVAT
    prelabels.xml             СКРИПТ: авторазметка для них
    verified/                 ВЫ кладёте сюда экспорт из CVAT (zip как скачался) — не удалять!
  dataset/                    СКРИПТ: всё генерируется, можно удалить и пересобрать
    images/<класс>/IMG_6883_ov0.jpg, _ov1, _ov2   испорченные копии (качество камеры весов)
    labels.csv                разметка
    params.json               параметры порчи каждой копии
```

В git хранятся только `raw/`, `esp32/` и `cvat/verified/` — всё остальное пересобирается командой.

Код:
- `build_dataset.py` — единственная команда, собирает всё выше.
- `ov2640_sim.py` — как портится фото (`degrade`) и как рамка переносится на испорченную копию (`map_box`).

## 2. Что делает `build_dataset.py`

Для каждого фото в `raw/`:

1. **Класс** = имя папки, в которой лежит фото.
2. **Только для `barcodes`:**
   - если фото уже проверено в CVAT (есть в `cvat/verified/`) — берёт разметку оттуда;
   - иначе читает коды zxing-cpp на оригинале (значение + рамка) и кладёт фото с этой авторазметкой
     в очередь на проверку: `cvat/upload.zip` + `cvat/prelabels.xml`.
3. **Делает 3 испорченные копии** (только если их ещё нет): размытие, шум, дисторсия, кривой баланс белого,
   разрешение SVGA/XGA/UXGA, сильный JPEG — как у камеры OV2640 на ESP32-CAM. Параметры → `params.json`.
4. **Переносит рамки кодов на копии** той же геометрией, что и порча (кроп 4:3, масштаб, дисторсия),
   и проверяет zxing, читается ли код на самой копии (`readable`).
5. Пишет `labels.csv` заново целиком.

Первый запуск — около 2 с на фото (порча), повторные быстрые: обрабатываются только новые фото.
В конце скрипт пишет, сколько фото ждут проверки в CVAT.

## 3. `labels.csv`

Одна строка = один объект. У фото еды — одна строка на копию без рамки. У фото штрихкода — по строке
на каждый код на копии (обычно один); если код не виден — одна строка без рамки.

| Колонка | Что это |
|---|---|
| `file` | путь к копии относительно `dataset/` |
| `source` | исходное фото в `raw/` — по нему группировать train/test |
| `class` | имя папки |
| `barcode` | значение кода; пусто — код не виден или не прочитан ни zxing, ни человеком |
| `x1, y1, x2, y2` | рамка кода **на этой копии**, в пикселях |
| `readable` | 1 — zxing прочитал на этой копии ровно это значение |
| `checked` | 1 — разметка фото проверена в CVAT, 0 — только автомат |

```python
import pandas as pd
df = pd.read_csv("custom_dataset/dataset/labels.csv", dtype=str)
imgs = df.drop_duplicates("file")                 # по строке на картинку — для классификатора
codes = df[df["barcode"].notna()]                 # коды с рамками
```

## 4. Как распознаётся штрихкод

**Цифры читает не нейросеть, а декодер zxing-cpp.** Он находит в кадре строки с чередованием
тёмных и светлых полос и меряет их ширину. EAN-13 — это 95 «модулей»: охранные полосы, 6 цифр по 7 модулей,
центр, ещё 6 цифр. Каждая цифра — свой рисунок из 4 полос, последняя цифра — контрольная, и результат
сверяется по нескольким строкам. Поэтому zxing либо даёт **точное** значение, либо ничего — не выдумывает.
DataMatrix «Честного знака» читается так же надёжно (коррекция ошибок Рида–Соломона), внутри него GTIN.

**Всё решают пиксели на одну полосу.** Самая узкая полоса EAN-13 — 0,33 мм; zxing нужно от ~2 px на неё.
Камера весов с 25 см видит кадр шириной ~26 см:

| Разрешение | px на полосу | Читается? |
|---|---|---|
| UXGA 1600×1200 | ~2 | на грани |
| XGA 1024×768 | ~1,3 | плохо |
| SVGA 800×600 | ~1 | нет |

Отсюда: кадр для штрихкода — в UXGA; фокус объектива ESP32-CAM подкрутить на 15–25 см;
не прочиталось — просить поднести код ближе (с 15 см ~3,5 px на полосу).

**Порядок на сервере** — сначала zxing, потом классификатор:

```
кадр → zxing (~20–50 мс)
   прочитал    → GTIN → база продуктов → готово
   не прочитал → классификатор
        «barcodes» → на экране «поднесите код ближе / поверните кодом к камере»
        еда        → топ-3 на экран
```

zxing дешевле и не ошибается; если бы первым стоял классификатор, его ошибка («это еда») теряла бы
читаемый код. Класс `barcodes` в классификаторе нужен, чтобы понять, что перед камерой упаковка,
когда код прочитать не удалось.

**Зачем тогда рамки кодов:** не для чтения (zxing ищет код сам), а чтобы (1) измерять, при каком размере
кода в пикселях чтение ломается, и (2) при необходимости обучить локализатор кода: вырезать код, увеличить
и прочитать ещё раз.

## 5. Проверка штрихкодов в CVAT

Формат в обе стороны родной — «CVAT for images 1.1», никаких конвертаций.

### Один раз: установка

1. Запустить **Docker Desktop** и дождаться «Engine running». Ошибка
   `open //./pipe/dockerDesktopLinuxEngine: The system cannot find the file specified` = Docker Desktop не запущен.
2. ```
   cd C:\Users\382he\cvat
   docker compose up -d
   docker exec -it cvat_server bash -ic "python3 ~/manage.py createsuperuser"
   ```
3. Открыть http://localhost:8080 (Chrome), войти.
4. Projects → «+» → любое имя → Labels → вкладка **Raw** → вставить и Done:
   ```json
   [{"name": "barcode", "type": "rectangle", "attributes": [{"name": "value", "mutable": false, "input_type": "text", "default_value": "", "values": [""]}]}]
   ```

### Каждая новая партия фото

1. `build_dataset.py` написал «Ждут проверки в CVAT: N фото».
2. Tasks → «+» → выбрать проект → загрузить `custom_dataset/cvat/upload.zip` → Submit.
3. Открыть задачу → Actions → **Upload annotations** → формат **CVAT 1.1** → `custom_dataset/cvat/prelabels.xml`.
4. Открыть job и пройти фото (`F` / `D` — следующее/предыдущее, `N` — новая рамка, `Del` — удалить, `Ctrl+S` — сохранить):
   - **рамка** — по штрихам, без цифр под ними и без белых полей (автоматическая обычно не той высоты — подвинуть);
   - **value** — цифры кода. Автоматические уже проверены контрольной цифрой. Если zxing не прочитал,
     а цифры под кодом видны — вписать; не видно — оставить пустым, не угадывать;
   - **кода на фото не видно** — рамок нет;
   - **несколько кодов** (EAN и DataMatrix) — рамка на каждый.
5. Actions → **Export task dataset** → **CVAT for images 1.1**, «Save images» выключено → скачанный zip
   положить в `custom_dataset/cvat/verified/` (имя любое).
6. Запустить `build_dataset.py`. Проверенные фото уйдут из очереди и получат `checked = 1`.
   Если в вписанном коде неверная контрольная цифра, скрипт напишет «ВНИМАНИЕ … опечатка?» — исправить
   в CVAT, экспортировать заново, заменить zip.

## 6. Почему у еды нет рамок

Классификатор (EfficientNet и т. п.) смотрит на **весь кадр** и учится только на метке класса — она
точная, потому что это папка, в которую вы положили фото. Камера закреплена над платформой, продукт
всегда в одном месте, искать его не нужно. Рамки нужны детектору (найти несколько объектов в кадре) —
его в плане нет.

## 7. Обучение

**Одна выборка, один классификатор** на все классы; `barcodes` — просто ещё один класс.
zxing не обучается. Отдельная модель может понадобиться только для локализатора кода (раздел 4).

Делить train/test **по исходному фото**, иначе копии одного снимка попадут и туда, и туда,
и точность будет завышена:

```python
import pandas as pd
from sklearn.model_selection import StratifiedGroupKFold

imgs = pd.read_csv("custom_dataset/dataset/labels.csv", dtype=str).drop_duplicates("file")
tr, te = next(StratifiedGroupKFold(n_splits=7, shuffle=True, random_state=0)
              .split(imgs, imgs["class"], groups=imgs["source"]))    # 1/7 ≈ 14% в test
train, test = imgs.iloc[tr], imgs.iloc[te]
# путь к картинке: "custom_dataset/dataset/" + train["file"]
```

Готовый скрипт с этим разбиением — `train.py` (сравнение B0–B4 и дообучение, результаты в `runs/results.csv`).

Если одна и та же упаковка снята несколько раз подряд, для строгой проверки штрихкодов группируйте
по значению `barcode`, а не по `source` — иначе в test окажется та же упаковка, что и в train.

## 8. Правила

- **Добавили фото** — просто запустить скрипт.
- **Удалили, переименовали или переложили фото в `raw/`** или **поменяли параметры порчи в `ov2640_sim.py`** —
  удалить папку `custom_dataset/dataset/` и запустить скрипт. `cvat/verified/` при этом **не трогать**.
- **Не переименовывать фото штрихкодов после проверки** — CVAT-разметка привязана к имени файла,
  иначе фото снова попадёт в очередь на проверку.
- **Как снимать:** так, как увидит камера весов — сверху, 25–30 см, продукт на столе/тарелке.
  Упаковки — лёжа, кодом вверх, часть кадров с 15–20 см. Не с рук перед собой: смаз и изогнутый код
  не прочитает даже zxing на оригинале.
- Ориентир для обучения — от 30 фото на класс.
